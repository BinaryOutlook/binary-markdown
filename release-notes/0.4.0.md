# Binary Markdown 0.4.0

**Status: release preparation; not yet published.** This source uses package version `0.4.0`. The [published release page](https://github.com/BinaryOutlook/binary-markdown/releases) establishes availability, source identity, and validated artifacts. [RC1's notes](0.4.0-rc.1.md) remain the record for that earlier human-review candidate; subsequent source changes do not replace its package or acceptance evidence.

Version 0.4.0 brings the editor and export work for issues #19–#40 together: easier formatting and table access, configurable writing space, searchable code languages, equation-source controls, and optional code metadata in PDF and Word exports.

## New features

- **Insert and format in place.** The Insert menu adds equations, tables, code, links, images, Mermaid diagrams, and a managed table of contents at the retained editing location. Underline uses paired `<u>` tags and is supported by the existing export formats, subject to reader compatibility.
- **Keep tables reachable.** Responsive controls expose overflow actions, docked controls use a contextual second row in Full mode, and wide tables scroll locally while keyboard navigation reveals the active cell.
- **Choose your writing space.** Use full width or a custom cap, align the capped column left, center, or right, and optionally show its width boundaries. These view settings do not reformat Markdown or change export paper dimensions.
- **Find code languages quickly.** Search readable names and aliases; browse the curated order or sort A–Z or Z–A. Changing the browsing order leaves code content intact.
- **Arrange equation source.** Place block-equation source above or below its preview and optionally wrap it visually without inserting source newlines.
- **Control exported code metadata.** Place PDF/DOCX language labels at any corner, show total authored-line counts, or enable per-line numbering independently. Numbering and counts follow logical source lines rather than visual wraps.

See the [editor guide](../docs/editor-guide.md) and [export help](../media/export-help.md) for exact behavior and settings.

## Changed defaults

| Preference | Unset value in 0.4.0 | Existing choices |
| --- | --- | --- |
| Formatting toolbar | Full | Explicit Full or Simple choices are retained. |
| PDF/DOCX language-label position | Top-left | Explicit positions are retained; choose bottom-right for the previous placement. |

The column still starts with a centered 860 px cap. Equation source remains above the preview with wrapping off. Code-line counts and numbering are independently off by default. The extension ID remains `BinaryOutlook.binary-markdown`, preserving update continuity.

## Fixes

- Keep blockquotes, links, and inline code readable across editor themes.
- Apply and save table-toolbar placement after one selection, with clear failure feedback and retained settings.
- Keep complete toolbar actions and table cells accessible during resizing and keyboard navigation.
- Keep inline equation edits open and cancellable during delayed outline updates or document synchronization.
- Preserve supported underline and authored code whitespace through the affected editing and export paths.

This version also carries the daily release-eligibility workflow, with a minimum three-day interval, full validation, and manual release support. The [release policy](../docs/releases-and-support.md#automatic-vsix-releases) defines its conditions; the interval is not a publication promise.

## Known limitations

- **DOCX numbering is experimental.** Microsoft Word, stable LibreOffice, interactive editing/copying, and spoken reading order still require acceptance in named reader versions. Syntax highlighting stays static after reader edits. An unnumbered long-block footer can move to the following page.
- **PDF copying can include gutter numbers** or group them separately from code. Inspect selection and reading order in your reader; a PDF is not a source-preserving code-copy format.
- **Underline uses inline HTML.** Other Markdown readers need `<u>` support. Actual Word/EPUB-reader appearance and accessibility need checks beyond converter structure tests.
- **Existing editor limitations remain.** The [integration review](../reports/validation/2026-09-20-editor-export-stack.md#remaining-acceptance-items) records rapid equation redo, the [#11 save-overlap concern](https://github.com/BinaryOutlook/binary-markdown/issues/11), and [#16 parser/spacing scope](https://github.com/BinaryOutlook/binary-markdown/issues/16). The previously disclosed [#5 numbered-list continuation issue](https://github.com/BinaryOutlook/binary-markdown/issues/5) is outside this feature work.
- Export remains limited to trusted, saved documents in supported local desktop VS Code hosts. Remote windows, browser VS Code, and Electron export remain outside scope. See [export limitations](../media/export-help.md#initial-format-limitations).

## Installation and validation

Use the [installation guide](../README.md#install) for an official package or the [build guide](../docs/building.md) for an identified source build. Select a published package by its release notes, source commit, and checksum. Package version `0.4.0` alone does not distinguish RC1, later development builds, and an eventual official release.

Validation targets the same VSIX on Ubuntu x86-64, macOS ARM64, and Windows x86-64, plus VS Code 1.85.0 on Ubuntu. Existing results in the [integration review](../reports/validation/2026-09-20-editor-export-stack.md) apply to their recorded revisions and environments. Required release validation and the remaining human acceptance checks must still be completed. The [release procedure](../docs/releases-and-support.md#maintainer-release-procedure) requires validation of the selected `main` commit before publication. Standalone desktop installers require separate release work.
