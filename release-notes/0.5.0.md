# Binary Markdown 0.5.0

Binary Markdown 0.5.0 brings the editor improvements integrated after 0.4.1 into one VSIX release scope. You can work in Visual, Source or Split, find commands and source matches, navigate tables, and wrap individual code blocks without changing their Markdown. [GitHub Releases](https://github.com/BinaryOutlook/binary-markdown/releases) identifies actual publication, source, validation and downloadable packages.

## Added and changed

- **Three editor views.** Visual editing, editable Markdown Source and Split with a read-only live preview share the same save route and Undo/Redo history. Outline/Document tabs and the footer expose headings, counts and section progress.
- **Searchable commands.** The permanent **More toolbar actions** menu searches formatting, insertion and view actions. The Insert workspace and Action Palette offer categories and previews. Collapsing the formatting row enables contextual tools for the current session.
- **Find and Replace on source.** Results show source lines and surrounding text. Case, whole-word and regular-expression matching, selected replacements and one-step undo work across views. Expensive searches are bounded, and truncated results disable Replace All.
- **Spatial table tools.** Row/column selectors, external cell coordinates, directional insertion and boundary append buttons act on the retained cell. Overflow menus and docking keep commands reachable in constrained panes.
- **Code wrapping and feedback.** **Wrap code** is off by default and applies per block for the current session. A persistent **Wrapped** badge distinguishes visual wrapping from authored source lines. Labeled copying and stable feedback retain exact code text; code controls stay above horizontally scrolling content.
- **Block and export feedback.** Equation and diagram blocks expose Source/Preview controls, plain-text diagnostics and source locations when reliable. Export shows progress, warnings and completion details without adding feedback to the Markdown.
- **Identified development packages.** Branch and PR builds carry their source commit, local-change state, workflow build number, run and attempt, plus checksum and build-information sidecars. These temporary packages are distinct from published releases.
- **Validation and dependency maintenance.** Four installed-VSIX lanes run alongside nine browser shards. Generated duplicate browser specs were removed, audited dependencies were updated, and scoped AI visual review remains separate from functional validation and owner acceptance.

The [editor guide](../docs/editor-guide.md) explains views, commands, source search, table navigation and code controls. The [changelog](../CHANGELOG.md#050) lists the integrated changes.

## Compatibility and defaults

Use local desktop VS Code 1.85.0 or later. Validation targets Ubuntu x86-64, macOS ARM64 and Windows x86-64, including VS Code 1.85.0 on Ubuntu. The extension remains `BinaryOutlook.binary-markdown`; settings and update continuity are retained. No new setting defaults or command IDs are introduced by this release-alignment branch.

Full toolbar mode, centered 860 px writing width, aligned formatting for edited tables and top-left export code labels retain their existing defaults. Explicit preferences remain honored. Code wrapping starts off and resets after reopening; it writes no document setting or source marker. Export line counts and numbering remain off by default.

Export remains experimental. It requires a saved, named document in a trusted supported local desktop VS Code workspace. HTML needs no converter; PDF needs Chrome/Chromium/Edge; DOCX and EPUB need Pandoc. Remote-SSH, browser VS Code and standalone Electron export remain outside scope. Keeping Electron manifest versions aligned does not release or validate standalone installers.

## Known limitations

- **Diagnostic keyboard scrolling needs investigation.** The inspected `main` run failed its macOS browser check for returning expanded diagram details to the top with Home. All required lanes must succeed for the final release source; see the [readiness record](../reports/validation/2026-10-07-0.5.0-readiness.md#automated-evidence).
- **External writes can replace unsaved edits.** Own-save protections do not add conflict recovery when another program changes the file. Preserve your work before external changes. Failed or uncertain saves defer automatic reload; see [saving and external changes](../docs/editor-guide.md#external-file-changes).
- **Markdown compatibility remains bounded.** Remaining inline-parser, escape, link/image destination, link-title and zero-width-space cases are carried forward from the [0.4.1 limitations](0.4.1.md#known-limitations). Source mode is available for inspecting authored text; no complete CommonMark/GFM conformance is claimed.
- **Reader acceptance remains incomplete.** Long custom DOCX language labels can extend beyond their tab in Word. DOCX numbering remains experimental, counts/highlighting do not recalculate after reader edits, and PDF copying can include gutter numbers. Review [export help](../media/export-help.md) and the historical [reader checkpoint](../reports/validation/2026-09-21-docx-reader-checkpoint.md).
- **Physical input and accessibility need human checks.** Browser and guarded native checks do not establish physical trackpad behavior, OS IME candidate selection, spoken screen-reader output, or every window/zoom combination.
- **Pending work is excluded.** Standalone HTML-anchor compatibility remains separate from the inspected `main` baseline. Standalone installers, Marketplace/Open VSX publication and remote export require their own decisions and validation.

## Installation and release validation

Follow the [VSIX installation instructions](../README.md#install) and retain the package checksum and build-information sidecar. After installing and reloading, run **Binary Markdown: Copy Build Information** and compare the version and full source commit with the sidecar. Development packages also expose their CI identity when present.

The [0.5.0 readiness record](../reports/validation/2026-10-07-0.5.0-readiness.md) identifies the inspected source, known validation failure and focused acceptance checklist. Historical feature checks do not validate a different candidate. Official publication requires the [maintainer release procedure](../docs/releases-and-support.md#maintainer-release-procedure): merge the reviewed scope, validate the actual `main` commit, promote those same package bytes and inspect the draft before publishing.
