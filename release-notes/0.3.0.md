# Binary Markdown 0.3.0

Binary Markdown 0.3.0 preserves recent code edits when switching between visual and source modes, keeps quoted code intact when saving, and adds table controls that adapt to the available space. Outline tracking and improved local links make longer documents easier to navigate.

## What changes for you

- **Keep code intact through editing and saving.** Switching to source mode captures pending edits. Saving after an unrelated edit preserves fenced code inside blockquotes, including its whitespace. Fences indented by one to three spaces render as code, inactive blocks regain syntax highlighting, and quoted code remains readable in light themes.
- **Put table controls where they work for you.** Automatic placement chooses available space around a table and moves the controls into the top bar when needed. You can also choose a fixed position or keep them in the top bar. Narrow panes provide a compact Table menu.
- **Follow your place and open local resources.** The outline highlights the section you are reading, with a configurable highlight color. Local file and folder links resolve correctly, show their destination on hover, and offer to copy the address when a target cannot be opened.
- **Remove code blocks directly.** A delete control removes the selected code block; Undo restores it.

Windows export-tool handling also improves: browser capability checks are shared across open editors, and distinct executable paths remain distinct.

## Known limitations

Two reported issues remain open. Numbered-list continuation paragraphs can lose their structure and numbering when saved ([#5](https://github.com/BinaryOutlook/binary-markdown/issues/5)). A separate native Save race can write an earlier revision when queued host edits overlap save preparation ([#11](https://github.com/BinaryOutlook/binary-markdown/issues/11)). The code-block fixes in this release do not resolve that save-queue race.

Export remains experimental; see [export help](../media/export-help.md) for supported formats, required tools, and existing limitations.

## Validation and installation

The release workflow validates the same VSIX on Ubuntu, macOS, and Windows, including installed-extension scenarios, real export tools, and browser regressions with retries disabled. It also checks the minimum supported VS Code version, 1.85.0, on Ubuntu. The published release identifies the exact source commit, validation run, and package checksums.

Download `binary-markdown-0.3.0.vsix` from the release assets, install it through **Extensions: Install from VSIX**, and reload VS Code. The extension retains its `BinaryOutlook.binary-markdown` identity and existing settings. See [supported platforms and release guidance](../docs/releases-and-support.md) for the validation scope; standalone desktop installers are outside this release.
