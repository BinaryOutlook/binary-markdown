# Binary Markdown 0.5.2

Binary Markdown 0.5.2 is a compatible update to [0.5.1](0.5.1.md). Its main fix keeps your unsaved edits when another program writes the file you have open. It also groups settings into categories, adds an option for icon-only code-block buttons, and colors the outline scrollbar to match the editor theme. The extension ID, your saved settings, and existing defaults are unchanged.

## At a glance

| Area | What changes | What you need to do |
| --- | --- | --- |
| Unsaved edits | Kept when another program writes the open file. A warning offers **Compare** and **Load Disk Version**. | Nothing. Choose an option when the warning appears. |
| Settings | Shown in six ordered categories in VS Code Settings. | Nothing. Every setting keeps its identifier and saved value. |
| Code blocks | Action buttons can show icons only. | Optional. Labels stay on unless you turn them off. |
| Outline | The scrollbar follows the editor theme. | Nothing. |

## Unsaved edits are kept when another program writes the file

In 0.5.1 and earlier, if another program wrote an open Markdown file while it had unsaved edits, Binary Markdown replaced your edits with the version on disk and cleared Undo. Examples include Git, a formatter, a sync service, or a second editor. [Issue #81](https://github.com/BinaryOutlook/binary-markdown/issues/81) recorded the problem.

In 0.5.2:

- A file without unsaved changes reloads as before. Tools that save by replacing the file are now detected too.
- A file with unsaved changes keeps them, and the document stays unsaved. The other program's version remains on disk. A warning names the file and offers two choices:
  - **Compare** opens VS Code's diff editor, with the other program's latest version on the left and your document on the right.
  - **Load Disk Version** replaces your unsaved changes with that version. Undo in Binary Markdown brings your edits back.
- Closing the warning keeps your edits. To see the choices again, select **Changed on disk** in the status bar or run **Binary Markdown: Resolve External Change** from the Command Palette. Saving, reverting, or loading a version ends the conflict.
- Text you typed just before the other program's write is kept the same way. Until you answer the warning, Binary Markdown holds the first save made with the editor's own shortcut; saving again writes your text.

Use **Compare** before saving over another program's change. VS Code asks before overwriting a newer file only when the file's size changed. See [external file changes](../docs/editor-guide.md#external-file-changes) for details.

## Settings are grouped into categories

Search for **Binary Markdown** in VS Code Settings to see six categories in this order: **Editor & Appearance**, **Outline**, **Writing Tools**, **Images**, **Export**, and **Advanced**. Table, code, and equation settings appear together under **Writing Tools**.

Only the arrangement changed. Every setting keeps its identifier, default, scope, and saved value, so you do not need to configure anything again. The [settings reference](../docs/editor-guide.md#vs-code-settings) follows the same order.

## Optional icon-only code-block buttons

To make code-block toolbars more compact, turn off the new `binary-markdown.codeBlockActionLabels` setting. It is on by default, so code blocks look the same as in 0.5.1 unless you change it.

With labels off, **Copy code**, **Wrap code**, and **Open in Text Editor** show only their icons. Their tooltips, accessible names, and keyboard actions remain. The language selector, the **Wrapped** badge, and copy-error messages stay visible. See [code controls and soft wrapping](../docs/editor-guide.md#code-controls-and-soft-wrapping).

## Other changes and fixes

- **Themed outline scrollbar.** Long outlines use scrollbar colors from the selected editor theme and update when the theme changes. High-contrast mode uses system colors.
- **Open in Text Editor with the keyboard.** Pressing Enter on a focused **Open in Text Editor** button now opens the text editor instead of adding a line to the code.
- **Dependency updates.** markdown-it is updated to 14.3.3 and Mermaid's bundled DOMPurify to 3.4.17 to resolve dependency audit findings. Patched build, packaging, and test tools are also pinned; those tools are not included in the extension package.

The [changelog](../CHANGELOG.md#052) lists these changes with the version history.

## Compatibility and defaults

Use local desktop VS Code 1.85.0 or later. The extension remains `BinaryOutlook.binary-markdown`, so installing 0.5.2 over 0.5.1 keeps your settings. No existing default changes. The new code-label setting defaults to the 0.5.1 appearance. **Binary Markdown: Resolve External Change** is a new command offered while an external-change conflict is unresolved.

The standalone desktop app's source gains matching Preferences sections and the code-label option, and its manifests also use `0.5.2`. This does not publish or validate standalone installers. External-change conflict handling applies to the VS Code extension.

## Known limitations

- **Saving over a same-size change.** VS Code asks before overwriting a newer file only when its size changed. Use **Compare** before saving when the other version matters.
- **Saves started by VS Code.** A save started from VS Code itself, such as **File > Save**, cannot be held during the typing race and writes your text. The warning still offers the other version.
- **VS Code 1.85.** **Load Disk Version** can bring the file's editor to the front. If that editor cannot be confirmed as active, VS Code's own newer-file prompt can still appear.
- **Translations.** The new external-change messages in the six non-English interface languages follow each language's existing terms but have not had a native-speaker review.
- **Earlier limitations.** The other [0.5.0 limitations](0.5.0.md#known-limitations) still apply: bounded Markdown compatibility, incomplete export-reader acceptance, and remaining physical-input and accessibility checks. 0.5.2 resolves the external-write limitation listed there.

## Installation and release validation

Follow the [VSIX installation instructions](../README.md#install) and retain the checksum and build-information sidecar. After installing and reloading, run **Binary Markdown: Copy Build Information** and confirm version `0.5.2` and the full source commit against the sidecar.

The changes were reviewed and validated in their pull requests: [#106](https://github.com/BinaryOutlook/binary-markdown/pull/106), [#109](https://github.com/BinaryOutlook/binary-markdown/pull/109), and [#110](https://github.com/BinaryOutlook/binary-markdown/pull/110). Those results apply to their recorded revisions. The release requires full validation of the resulting `main` commit.
