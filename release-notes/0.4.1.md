# Binary Markdown 0.4.1

Binary Markdown 0.4.1 improves everyday editing and source preservation: paragraphs, tables, ordered lists, inline code, and the latest text when saving. This patch brings together the paragraph/table improvements and the pre-release correctness fixes.

## Changed

- **Paragraphs follow Markdown structure.** Enter creates a paragraph; Shift+Enter creates a hard line break. Unchanged blocks and their separators retain their source spelling.
- **Tables keep their existing source until edited.** Editing another block leaves an untouched table intact. New or edited tables use aligned Markdown columns by default, with **Compact (Legacy)** available through the [table source format setting](../docs/editor-guide.md#table-source-format). Changing the setting alone does not rewrite a table.
- **Guides reflect the current editor and release scope.** Installation, settings, export help, testing and release guidance now agree on feature availability, command labels and known limitations.

## Fixed

- **Paragraph spacing and hard breaks.** Ordinary source wraps and blank separators no longer create extra visible paragraphs. Paragraph boundaries, explicit hard breaks and loose-list continuation survive saving and reopening.
- **Table alignment.** Explicit left, center and right alignment applies to headers and body cells, including header-only tables after editing in either source format.
- **Ordered lists and checklists.** Authored starting numbers, including zero, and ordered checkbox markers survive visual edits, including mixed and nested lists.
- **Literal inline code.** Literal `<br>`, meaningful padding, space-only spans and embedded backticks survive supported edits and save/reopen, including code inside table cells.
- **Save and Undo/Redo.** Native Save commits the latest captured snapshot after earlier queued edits. File-watcher reloads wait for completed writes and stay deferred when newer edits make the saved revision uncertain, preventing older or partial disk content from replacing those edits. Immediate Undo followed by Redo retains the latest typed changes.
- **Test and documentation checks.** Local commands and CI discover the same complete unit suite. Native Insert-menu checks have bounded waits, fixture cleanup preserves unrelated dirty editors, and documentation checks correctly handle Markdown links and anchors.

## Compatibility and defaults

Use local desktop VS Code 1.85.0 or later. Validation targets Ubuntu x86-64, macOS ARM64 and Windows x86-64, including VS Code 1.85.0 on Ubuntu. The extension remains `BinaryOutlook.binary-markdown`, retaining existing settings and update continuity.

New or edited tables use aligned source formatting by default; unchanged tables retain their source. Toolbar, editor-width and export settings retain the 0.4.0 defaults and explicit user choices. Export remains experimental and requires a trusted workspace and a saved document in supported local desktop VS Code hosts. Remote-SSH, browser VS Code and standalone Electron export remain outside scope.

## Known limitations

- **External writes can still replace unsaved edits.** The Save fixes do not add conflict handling when another program changes the same file. Save your work before external changes; [#81](https://github.com/BinaryOutlook/binary-markdown/issues/81) remains open. See [saving and external changes](../docs/editor-guide.md#external-file-changes).
- **An uncertain save defers automatic reload.** A failed save or an intervening edit leaves watcher reload deferred until a later unambiguous successful save or closing and reopening the editor. Preserve unsaved text before reopening. Cancelling an export does not cancel an active disk write.
- **Some Markdown cases remain unresolved.** Broader typography and CommonMark/GFM alignment ([#16](https://github.com/BinaryOutlook/binary-markdown/issues/16)), backslash escapes ([#76](https://github.com/BinaryOutlook/binary-markdown/issues/76)), balanced link/image destinations ([#77](https://github.com/BinaryOutlook/binary-markdown/issues/77)), authored zero-width spaces ([#83](https://github.com/BinaryOutlook/binary-markdown/issues/83)) and optional link titles ([#85](https://github.com/BinaryOutlook/binary-markdown/issues/85)) remain follow-up work.
- **Export-reader acceptance is incomplete.** A long custom DOCX language label extended outside its tab in Word. PDF selection/copy, all label/count/numbering combinations, Word/LibreOffice editing, EPUB appearance and the HTML reader review still need acceptance. Underline passed the observed Word and Preview cases. See [reader observations](../reports/validation/2026-09-29-0.4.1-readiness.md#reader-observations) and [export help](../media/export-help.md).
- **DOCX numbering remains experimental.** Enter on an empty numbered line can end numbering or change formatting. Counts and syntax highlighting do not recalculate after reader edits, and PDF copying can include gutter numbers. The [DOCX checkpoint](../reports/validation/2026-09-21-docx-reader-checkpoint.md) retains the earlier named-reader evidence.
- **Standalone installers require separate work.** Electron dependencies ([#86](https://github.com/BinaryOutlook/binary-markdown/issues/86)) and installer validation are outside this VSIX release scope.

## Installation and validation

Download available packages and checksums from [GitHub Releases](https://github.com/BinaryOutlook/binary-markdown/releases), then follow the [VS Code installation instructions](../README.md#install). The published release identifies its exact source, package checksum and validation run. Use the [build guide](../docs/building.md) for source builds.

The [pre-release readiness record](../reports/validation/2026-09-29-0.4.1-readiness.md) records successful automated checks and the maintainer's manual success report at the earlier revisions and artifacts it identifies. Those results establish the correction batch's evidence and remaining acceptance work. The final `main` package must pass the [release procedure](../docs/releases-and-support.md#maintainer-release-procedure) before those same validated bytes are published.
