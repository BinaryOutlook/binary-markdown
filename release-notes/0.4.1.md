# Binary Markdown 0.4.1

**Status: first draft for final release review, dated 2026-09-29.** The 0.4.1 correctness work has passed automated validation, and the maintainer reports successful manual checks. Version 0.4.1 is the selected release target; no 0.4.1 package or release has been published. The latest official package remains [0.4.0](https://github.com/BinaryOutlook/binary-markdown/releases/tag/v0.4.0).

This patch focuses on preserving what you write: paragraph boundaries, table source, ordered lists, inline code, and the latest text when saving. It combines the paragraph/table work already integrated through [PR #80](https://github.com/BinaryOutlook/binary-markdown/pull/80) with the correctness fixes in [PR #91](https://github.com/BinaryOutlook/binary-markdown/pull/91).

## Editing and source preservation

- **Keep paragraph meaning without extra gaps.** Ordinary source wraps and blank separators no longer become extra visible paragraphs. Enter creates a paragraph; Shift+Enter creates a hard line break. Unchanged blocks and their separators retain their source spelling.
- **Keep existing table formatting.** Editing another block leaves an untouched table's source intact. New or edited tables use aligned Markdown columns by default; choose **Compact (Legacy)** through the [table source format setting](../docs/editor-guide.md#table-source-format). Changing the setting alone does not rewrite a table. Explicit left, center and right alignment applies to headers and body cells, including header-only tables.
- **Keep authored list starts and checklists.** Ordered lists retain their starting number, including zero. Editing or toggling ordered checkboxes preserves the ordered list type and numbering, including mixed and nested cases.
- **Keep inline code literal.** Literal `<br>`, meaningful padding, space-only spans and embedded backticks survive supported edits and save/reopen, including code inside table cells.
- **Keep the latest text through Save and Undo/Redo.** Native Save commits the current captured snapshot after earlier queued edits. Own-save watcher events wait for completed writes, and older or partial disk content cannot replace newer edits during that save flow. Immediate Undo followed by Redo retains the latest typed changes.

These are focused preservation fixes. The broader CommonMark/GFM and typography work in [#16](https://github.com/BinaryOutlook/binary-markdown/issues/16), and the remaining parser cases listed below, remain open.

## Compatibility and defaults

Use local desktop VS Code 1.85.0 or later. The validated CI scope covers Ubuntu x86-64, macOS ARM64, Windows x86-64, and VS Code 1.85.0 on Ubuntu. The extension remains `BinaryOutlook.binary-markdown`; existing settings and update continuity are retained.

Aligned source formatting is the default for newly created or edited tables. Existing unchanged table source remains intact. Toolbar, editor-width and export settings retain the 0.4.0 defaults and explicit user choices. Export remains experimental and limited to trusted, saved documents in supported local desktop VS Code hosts. Remote-SSH, browser VS Code, and standalone Electron export remain outside scope.

## Known limitations

- **External writes can still replace unsaved edits.** The own-save fixes do not implement a conflict workflow for another program modifying the same file. Review/keep-local/use-disk controls are absent; [#81](https://github.com/BinaryOutlook/binary-markdown/issues/81) remains open. Save your work before another program changes that file. See [saving and external changes](../docs/editor-guide.md#external-file-changes).
- **An uncertain save defers automatic reload.** A failed save or an intervening edit leaves watcher reload deferred until a later unambiguous successful save or closing and reopening the editor. Preserve unsaved text before reopening. Cancelling an export does not cancel an active disk write.
- **Some inline syntax still needs work.** Backslash escapes ([#76](https://github.com/BinaryOutlook/binary-markdown/issues/76)), balanced link/image destinations ([#77](https://github.com/BinaryOutlook/binary-markdown/issues/77)), authored zero-width spaces ([#83](https://github.com/BinaryOutlook/binary-markdown/issues/83)), and optional link titles ([#85](https://github.com/BinaryOutlook/binary-markdown/issues/85)) are outside this correction batch. Source preservation is not a claim of complete CommonMark/GFM conformance.
- **Export-reader acceptance is incomplete.** A long custom DOCX language label extended outside its tab in Word. PDF selection/copy, the complete label/count/numbering combinations, and the Word/LibreOffice editing matrix still need acceptance. Underline passed the observed Word and Preview cases; EPUB visual acceptance and the HTML reader review remain incomplete. See [reader observations](../reports/validation/2026-09-29-0.4.1-readiness.md#reader-observations) and [export help](../media/export-help.md).
- **DOCX numbering remains experimental.** Enter on an empty numbered line can end numbering or change formatting. Counts and syntax highlighting reflect the exported source and do not recalculate after reader edits. PDF copying can include gutter numbers. The [DOCX checkpoint](../reports/validation/2026-09-21-docx-reader-checkpoint.md) retains the earlier named-reader evidence.
- **Standalone installers have separate requirements.** The Electron dependency work in [#86](https://github.com/BinaryOutlook/binary-markdown/issues/86) and installer validation are outside this VSIX release scope.
